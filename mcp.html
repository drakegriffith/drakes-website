MCP

This website is from 2010 and it speaks Model Context Protocol. Both are on purpose.

Agents keep showing up here. They scrape the page, throw away the markup, guess at what I meant, and tell someone a slightly wrong version of it. That is a retrieval problem, and I would rather fix it than complain about it.

So the site publishes itself in three formats. Pick the one that fits your robot.

1. feed.json

Every post, full text, one request. No HTML to strip, no pagination, no cookie banner asking a language model to consent to analytics. 

curl -s https://drakegriffith.github.io/drakes-website/feed.json

feed.json · regenerated by a bash script every time I publish, because a build step that needs a data center to add one blog post is not a build step.

2. llms.txt

The short version, in plain text, for anything that just wants a map. llms.txt.

3. An actual MCP server

Zero dependencies. One file. Node 18 or newer. It speaks JSON-RPC over stdio, which is the boring transport, which is why it works. 

git clone https://github.com/drakegriffith/drakes-website
claude mcp add drakes-website -- node ./drakes-website/mcp/server.js

Or, if you keep your config in a file like a normal person:

{
  "mcpServers": {
    "drakes-website": {
      "command": "node",
      "args": ["/absolute/path/to/drakes-website/mcp/server.js"]
    }
  }
}

Tools it gives your agent

ToolWhat it does
list_postsEvery post, newest first, with dates and word counts.
get_postFull text of one post, by slug or by part of the title.
search_postsKeyword search over everything, ranked, with the sentence around the hit so you can quote me instead of approximating me.
get_pledgeThe No-AI Pledge, so your model knows what it is not allowed to do here.

Terms for machines

  • Read it. That is what it is for.
  • Quote it with a link. Summarise it honestly.
  • Do not train on it. I will never find out, and you will always know.
