I spent about a week building a controlled experiment to find out whether my own setup is worth anything, and then I killed it. The setup is the pile of stuff I have bolted onto Claude Code over the last few months. A vault of notes, a stack of skills, a router file that tells the agent which skill to grab, a context layer, and a memory system that carries what I learned in one repo into every other repo. It all feels useful. Feels. Nobody had measured it, me least of all.

So: ablation study. Same tasks under the full stack, then again with one piece pulled out at a time, and whatever hurts when you pull it is the piece doing work. 167 reps per cell. 8,183 runs. Pre-registered and frozen before a single run so I could not drift the goalposts once numbers started landing, which I would have.

Zero of those runs happened.

The gate that ate it

Before a task's first scored run there is a check that greps every memory store on the machine for that task's distinctive strings. If the answer is already sitting somewhere an agent can retrieve, I am not measuring reasoning, I am measuring lookup. Any hit burns the task. Fail-closed, no override switch, because the only person who would ever reach for the override is me at 1am wanting the number.

All seven tasks burned. Nothing scored, ever.

The first cause is embarrassing and boring. I had sub-agents write the tasks on this machine, so every task matched its own authoring transcript. Transcripts are memory. I knew that. I had written it down in the same repo a week earlier, in a file about this exact hazard. Moved the authoring off the machine, re-scanned, four of seven came back clean.

Then the second cause.

The memory system had already filed it

My cross-project memory had consolidated pieces of the experiment into records belonging to two unrelated projects. Spec revisions, task file paths, and in one case the literal edit that introduced a task's answer string, sitting in a record filed under a project that has nothing to do with any of this.

Nothing read the experiment's repo. There was no crawl to block, no directory to add to an ignore list, no leak in the sense of something escaping through a hole. The content showed up pre-formed, already summarized, filed while I worked. The memory system was doing the job I built it for. The job is to notice what I am doing and make it available later, in every other project. It did that. It is good at it.

And two of the conditions under test are memory and vault access. That is what kills it. The leak is not even across arms. The full-stack arm can retrieve the leaked answer, the stripped-down arm cannot reach it, so some slice of whatever gap I measured is my own experiment handed back to me, and I would have read that slice as the harness earning its keep. Which is the claim. That is the whole thing I sat down to test.

If you run agent memory across projects and you also want to evaluate those agents on anything, this is sitting there waiting for you. Your eval material is material. It gets consolidated like everything else. The isolation you think you have is repo-shaped, memory ignores repo shape, that is the product.

The bit I liked less

Writing up the kill I reread my own pre-registration and found something worse than the leak, which is a sentence I did not enjoy typing.

Three tasks. One per task shape. 8,183 runs across three tasks. All that repetition buys precision and precision is not generality, so I would have finished with a very tight measurement of three specific tasks and no standing to say a word about a fourth. The limitation is written into the pre-registration. In my own words. I read it during review and approved it, because the run count looked serious and I wanted to start.

So the clean version of this experiment was going to hand me a number I could not use. I got saved from that by a grep.

What I am doing instead

Bake-off on real tickets out of live repos. Full stack against bare, same ticket, judged blind. Contamination stops mattering once the tasks are work I wanted done anyway, and if the harness wins partly by retrieving something it stashed earlier, fine, that is the harness doing its job. Looser instrument. Worse paper. Measures a thing I care about.

The actual mistake was sequencing. I built the apparatus first, all of it, pre-registration and frozen spec and an adversarial review panel and contamination scanning and isolation proofs, and the apparatus is good. I built it before checking whether the thing I wanted to measure was measurable on this machine, with this memory running, on tasks of this kind. That check is an afternoon. It goes first, and I knew that, and I did it in the other order anyway.
